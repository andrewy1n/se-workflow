## Problem

The dashboard lists tasks, but you cannot see what a task asks for, how it is checked, or what the agents did on it.

## Approach

`dashboard_model` gains a task-detail loader: one `list --subject <slug> --full` call for the task's records, plus `get` on the work-item for its `depends_on` edges. In the app, Enter or a mouse click on a task row opens a detail screen. The screen shows a header (title, status, phase, wave, assignee, depends on, blocks), the description as rendered markdown, each acceptance with its latest check-run result and signer, a timeline of assignments, amendments, execution reports (bodies collapsible), and check-runs, and any findings, decisions, or failed attempts on the task. Esc returns to the dashboard with the cursor kept. The screen refreshes on store change.

## Exit criteria

Selecting a task by Enter or click opens its detail screen with every section above filled from the store, readable at 60 and 160 columns, live on store change, and Esc returns to the same row. The full suite passes. The user signs off on the detail screen in the popup and the side pane.
