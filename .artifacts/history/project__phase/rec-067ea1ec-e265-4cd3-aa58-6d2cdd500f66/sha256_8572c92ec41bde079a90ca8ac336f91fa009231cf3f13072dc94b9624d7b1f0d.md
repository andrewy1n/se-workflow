## Problem

`project:active-goal` is a current-claim: `active -> superseded` only. A finished effort stays live forever, so finished efforts crowd the handoff and the dashboard.

## Approach

Keep the record types. Add an optional `status` payload field (`open` | `closed`) to `active-goal` and `current-position`. Closing an effort supersedes both with `status: closed`. View roles for goal and position select `payload.status != closed`, so existing records without the field stay visible. The dashboard model skips closed goals. execute-phase gets a close step after the last phase of an effort.

A pattern switch to `commitment` was rejected: existing goal records lack `adoption_or_deontic_status` and would fail validation, and records cannot be rewritten by hand.

The live store's design is updated in `effort-merge`, when no other session writes to the store.

## Exit criteria

- A goal and position superseded with `status: closed` no longer appear in handoff, brief or dashboard views; records without `status` still do.
- The dashboard model drops closed efforts.
- execute-phase tells the agent how to close an effort after its last phase, and the skill/contract consistency tests pass.
