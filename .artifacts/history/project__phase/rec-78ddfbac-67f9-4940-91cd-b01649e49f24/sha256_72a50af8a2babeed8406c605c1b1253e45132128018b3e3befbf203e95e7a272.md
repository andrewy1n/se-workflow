## Problem

The plan says what a task is and how to prove it, and execution always spawns one subagent per ready task. The recipe gets negotiated while the work is running, and a wave cannot be done in this session even when it is one small change or the closing verification.

## Approach

Decisions: wave-executor-mode, task-recipe, phase-run-facts.

Each new task carries an `## Approach` section with the implementation recipe. Each wave is either `inline` (this session) or `subagent` (one worker per task, in parallel). Every task in a wave uses the same executor. There is no workflow executor. A missing executor means `subagent`, so existing tasks still run. Execution follows the recipe and does not ask how.

Size: one sitting.
Stops: plan review before dispatch. No manual sign-off.
Collisions: none. `plan-wave-rules` owns `skills/plan-phase/SKILL.md`, `contract/project-design.json`, `skills/kinds-and-focus.md`, `README.md`, and `tests/test_plan_wave_rules.py`. `execute-wave-dispatch` owns `skills/execute-phase/SKILL.md` and `tests/test_execute_wave_dispatch.py`. `verify-wave-executor` owns `tests/test_wave_executor_phase.py`.

## Exit criteria

- `plan-phase` requires a recipe, one shared executor of `inline` or `subagent` per wave, and the phase size, stops, and collision notes, and it does not open plan review until those are present. `python3 -m pytest tests/test_plan_wave_rules.py -q` passes.
- `execute-phase` runs an inline wave in this session and a subagent wave as one worker per task, treats a missing executor as `subagent`, and does not ask for a recipe when `## Approach` is present. `python3 -m pytest tests/test_execute_wave_dispatch.py -q` passes.
- The two skills name the same executors. `python3 -m pytest tests/test_wave_executor_phase.py -q` passes.
