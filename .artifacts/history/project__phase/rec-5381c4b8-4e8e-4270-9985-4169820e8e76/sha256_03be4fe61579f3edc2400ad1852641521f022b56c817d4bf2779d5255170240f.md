## Problem

Each phase proves its own piece. Nothing yet proves the pieces work together during a real workflow run.

## Approach

1. e2e-scripted-run: one test drives the whole chain. A scratch repo is adopted through the CLI, with a goal, a phase and three chained work-items. An isolated tmux server loads the conf, a pty client attaches, and prefix + S opens the side pane running `watch`. The test moves tasks through their lifecycle and adds and answers a blocking question. After each step it waits for the side pane to redraw and checks the section map, and it checks the status segment line.
2. e2e-real-execute-run: the parent runs a real execute-phase wave with subagents on a scratch effort (two small dependent tasks) while `watch` runs in an isolated tmux server. A capture loop logs every distinct frame. The frame log is the evidence; the user signs it.
3. verify-end-to-end-phase (depends on 1 and 2): all checks and the final effort state.

## Exit criteria

- The scripted end-to-end test passes: verified by running it.
- The real run's frame log shows each task go ready, running, done, and the dependent task go waiting, ready, running, done: verified by the user reading the log and signing the manual check-run.
- Both full suites pass: verified by running them.
- The watch-dashboard dashboard shows no Open Question, Needs Human, or Unsigned Manual Check: verified by rendering it after the user signs and answers the open question.
