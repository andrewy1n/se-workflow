## Problem

Each phase proves its own piece. Nothing yet proves the pieces work together during a real workflow run.

## Approach

1. Scripted end-to-end run: create a scratch git repo, adopt it, write goal, phase and dependent work-items through the CLI. Start `watch` in a detached tmux session (popup binding and side pane). Move tasks through planned, in_progress and done, add and answer a blocking question. After each step, `tmux capture-pane` and assert the dashboard and the status line line.
2. Real run: one execute-phase wave with subagents on a scratch effort while the popup is open. The user watches it and signs off a manual check-run.

## Exit criteria

The scripted end-to-end run passes. The real run has a manual check-run with signed_by set. The dashboard view shows no open question, needs-human finding, or unsigned manual check for watch-dashboard.
