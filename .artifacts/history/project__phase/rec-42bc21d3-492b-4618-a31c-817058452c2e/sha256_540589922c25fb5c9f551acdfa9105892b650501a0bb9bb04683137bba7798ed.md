## Problem

A task has no record of how big it is or how long the agent who will do it should take. The phase body records session shape as `one sitting` or `more than one`, and the work-item records `executor` as `inline` or `subagent`. Neither is a duration. The contract has no `size` or `estimate_minutes` field, so those values cannot be stored yet.

## Approach

Decisions: task-agent-estimate, glance-run-facts.

Each new work-item stores `size` and `estimate_minutes` for its executor. `size` is `XS` a trivial or local change, `S` a small change, `M` a moderate change, `L` a substantial or multi-file change, or `XL` a large or high-risk change. `estimate_minutes` is a non-negative integer. Absent means unset, and zero is a real estimate. `plan-phase` writes both with the executor. A missing executor means the minutes are for a subagent. Size and `estimate_minutes` are not derived from each other.

The phase does not store either field. Inline minutes in a wave add. A subagent wave's elapsed estimate is its longest task. Phase elapsed time adds those wave figures in wave order. The sitting line stays.

Dashboard display waits for a later phase. When that phase shows the sitting line and the executor, it uses title suffixes. This phase does not render size, `estimate_minutes`, the sitting line, or the executor.

## Exit criteria

`contract/project-design.json` allows optional `size` (`XS`, `S`, `M`, `L`, `XL`) and optional `estimate_minutes` on `project:work-item`. `skills/plan-phase/SKILL.md` requires both on each new work-item, states the five size meanings, the inline sum, the subagent-wave maximum, the phase elapsed time, and the sitting line. `python3 -m pytest tests/test_skill_contract_consistency.py -q` passes. The phase does not change `dashboard/`.
