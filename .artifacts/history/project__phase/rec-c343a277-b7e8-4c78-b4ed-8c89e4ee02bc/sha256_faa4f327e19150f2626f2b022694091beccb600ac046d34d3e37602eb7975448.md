## Problem
Per-session summaries do not show patterns across sessions. Per-session record counts are approximate, because 70% of record-to-session joins are ambiguous.

## Approach
Add scripts/session_aggregate.py. It reads the JSONL from session_report.py --records and prints one JSON document with four parts. Per effort: sessions, turns, tool calls, errors, retries and cost, where a session counts toward an effort when a record of that effort falls in its window. Cost splits into exclusive and shared, so double counting is visible. Across all sessions: error and retry rates per tool, and skill usage. Outliers: the sessions with the most errors, retries and cost, as references only. Each part is a separate module with its own tests. The document carries a caveats field naming the ambiguous share. Output holds counts and references only.

## Exit criteria
A fixture report with three sessions and two efforts yields the expected per-effort totals, tool and skill rollups, and outlier order. The real run over this machine's report prints valid JSON with every effort in the store that has a session, and exits 0.
