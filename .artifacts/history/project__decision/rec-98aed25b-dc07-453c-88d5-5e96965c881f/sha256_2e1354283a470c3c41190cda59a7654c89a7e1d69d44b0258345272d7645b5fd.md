## Rationale

Task-level acceptance only proves each unit. A verification task that depends on the rest of its phase makes "phase done" a checkable fact, and the dashboard itself then shows the gate. A final end-to-end phase proves the view, renderer, tmux wiring and a real execute-phase run work together.

## Counter-argument

Integration tests that drive tmux are slower and more fragile than unit tests. The real-run sign-off is manual, so the effort cannot close without the user.
