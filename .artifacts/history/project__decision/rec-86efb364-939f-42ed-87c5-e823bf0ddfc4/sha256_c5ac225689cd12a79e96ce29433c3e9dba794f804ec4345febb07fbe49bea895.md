## Rationale

S, M, and L say how big the change is. Minutes say how long the agent who will do that task is expected to work. Agent runs land in minutes, so an hour field rounds a 10-minute task and a 40-minute task into the same rough bucket. `plan-phase` already names that agent as `inline` or `subagent`, so the minutes are written for that executor. Inline tasks are one agent working in sequence, so their minutes add. Subagent tasks in one wave run at the same time, one worker each, so that wave's elapsed estimate is its longest task. Adding every task in the phase would treat those workers as one agent. The phase stores neither field. Phase elapsed time is those wave figures added in wave order. Size and minutes are not derived from each other, so a large task with a short minute estimate stays visible. The dashboard does not change in this phase.

## Counter-argument

Hours match how a person budgets a day, and a phase elapsed time in minutes will be a large number once several waves add up. One sum of every task's minutes would also be a single figure to set next to a deadline, without the wave rule.
