## Rationale
Records have no session id and adding one needs a contract change in both plugins. A time window plus the project name uses fields that exist today. The CLI list is the stable public interface to the store, so the join does not depend on the storage layout.

## Counter-argument
Overlapping sessions in one project make some attachments ambiguous, and clock skew could misplace records near window edges. A session id on each record would remove both problems. If the ambiguity rate turns out high, add the session id to the contract.
