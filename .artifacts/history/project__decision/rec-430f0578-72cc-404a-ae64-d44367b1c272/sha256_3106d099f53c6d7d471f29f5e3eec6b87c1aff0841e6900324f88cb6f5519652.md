## Rationale

S, M, and L say how big the change is. Hours say how long the agent who will do that task is expected to work. `plan-phase` already names that agent as `inline` or `subagent`, so the hours are written for that executor. Inline tasks are one agent working in sequence, so their hours add. Subagent tasks in one wave run at the same time, one worker each, so that wave's elapsed estimate is its longest task. Adding every task in the phase would treat those workers as one agent. The phase stores neither field. Phase elapsed time is those wave figures added in wave order. Size and hours are not derived from each other, so a large task with a short hour estimate stays visible. The dashboard does not change in this phase.

## Counter-argument

One sum of every task's hours is a single number to set next to a deadline. Splitting inline and subagent time, and using the longest task for a parallel wave, means the phase elapsed time is not the total agent effort, and a reader has to know the wave rule to see where the number came from.
