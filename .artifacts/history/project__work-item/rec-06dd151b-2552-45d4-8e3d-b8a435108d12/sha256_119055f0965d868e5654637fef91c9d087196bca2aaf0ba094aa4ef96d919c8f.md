## Description

## Approach

Edit `skills/engage/SKILL.md`, `skills/ensure-store.md`, and `README.md` (and `skills/kinds-and-focus.md` only if a clear/capture rule belongs there). Do not edit `contract/project-design.json`.

- Keep the existing feedback rule: list feedback, route through discuss, do not collect or create feedback.
- After focus is named, list open backlog-item for that effort (`payload.status=open`).
- When the user parks work, create backlog-item via CLI (parent writer); when they start an item, supersede to promoted and route to discuss with phase new (or incidental work-item when that kind fits); dismiss supersedes to dismissed.
- Add `backlog-item` to the ensure-store currency checklist next to feedback.
- README: one short paragraph distinguishing feedback (route now) from backlog-item (park then promote). Document the create/list/supersede shapes from the design.

Prove documented invocations with `uv run --with pytest python -m pytest tests/test_skill_contract_consistency.py tests/test_assess_routing.py -q` (extend or add assertions that engage still forbids creating feedback and documents backlog-item list/create/supersede).
