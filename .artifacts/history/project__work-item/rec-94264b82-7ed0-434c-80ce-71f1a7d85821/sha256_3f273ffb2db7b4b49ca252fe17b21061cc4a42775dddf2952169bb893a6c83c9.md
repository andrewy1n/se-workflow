## Description

Teach `execute-phase` to create the phase worktree and to commit and merge when the phase gate holds.

## Approach

Edit `skills/execute-phase/SKILL.md`.

After plan review is answered and before the first wave, read `## Landing` from the phase body. When it is present, create branch `phase/<phase-slug>` from `main` if that branch is missing, and add the worktree at `<repo-parent>/<repo-name>--<phase-slug>` if that path is missing. Inline work runs in that directory. Each subagent is given the worktree absolute path and writes code only under that path. The parent writes `.artifacts` only on the primary checkout. The phase branch commit excludes `.artifacts`.

When the phase gate holds, commit the code from the worktree, merge `phase/<phase-slug>` into `main` from the primary checkout, then commit the store on `main`. When Landing names push as a human stop, stop before pushing and ask. Otherwise do not push.

When the phase body has no Landing section, keep the current checkout and do not create a branch. Incidental work stays in the current checkout too.

Add `tests/test_execute_landing.py`. Assert the skill text contains the worktree path `<repo-parent>/<repo-name>--<phase-slug>`, code writes only under the worktree, store writes on the primary checkout, commit the phase branch, merge into `main`, commit the store, push only when it is a human stop, and a missing Landing section stays in the current checkout.

Do not edit `skills/plan-phase/SKILL.md`.
