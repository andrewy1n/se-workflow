## Description

Add per-effort phase-selection helpers to the dashboard model: default phase from most-recent activity, follow/pin semantics, no-phase fallback, and merged activity lines.

## Approach

1. Add a `Selection` dataclass to `dashboard/model.py` with `phase` (str or None for All phases), `pinned` flag, and `follows_default` flag.
2. Add `default_phase(view)` that returns the in-progress phase with the most recent activity, else the lowest-ordinal planned phase, else None (All phases).
3. Add `resolve_selection(view, previous)` that follows the default when not pinned, resumes following when the user re-selects the current default, and falls back when the pinned phase disappears.
4. Add `merge_activity(items)` that collapses consecutive same-kind, same-outcome activity items into one line naming their subjects.
5. Update `EffortView` construction so an effort with no phases exposes an empty phase list and no selector state.
6. Add unit tests in `tests/test_dashboard_model.py` for default selection, follow/pin, activity merge, and the no-phase case.
