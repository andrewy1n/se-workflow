## Description

Make the full suite at least 2x faster without adding CPU load. Most time goes to `adaptive-artifacts` subprocess calls and to tmux tests that wait out a deadline.

Steps:
1. Measure first. Run `uv run --with textual --with pytest python -m pytest tests -q --durations=15` once and record the wall and CPU time. Plain `python3 -m pytest` lacks textual and makes the tmux tests fail, so it is not a valid baseline.
2. Build each seeded store once per session in `tests/conftest.py`. Copy it per test. Start with `tests/test_dashboard_model.py`, where each test spends about 1.3s in setup.
3. Give pure layout pilot tests a built snapshot instead of the CLI. Keep a few end-to-end tests on the real CLI.
4. For slow tmux tests, find why the expected text never shows. Fix that cause.

Do not:
- raise any timeout or deadline, in `wait_for` or anywhere else. A test that needs a longer deadline has a bug to fix.
- add pytest-xdist or any parallel runner.
- skip or delete tests.

Edit tests only. Do not touch the uncommitted dashboard changes in `scripts/dashboard_app.py`. Start after task-navigation is done, because both edit the same tests.
