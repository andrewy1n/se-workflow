## Description

Make the full suite at least 2x faster without adding CPU load.

Measured baseline (clean HEAD 2d1a3be, `uv run --with textual --with pytest python -m pytest tests -q`): 262 passed, 317s wall, 209s user + 40s sys CPU. Plain `python3 -m pytest` lacks textual, so tmux and app tests fail there. It is not a valid baseline.

Diagnosis:
- `tests/test_dashboard_app.py` has 108 tests and uses about 2.7s each. One test, profiled: 1.0s fixture setup, 1.6s call. The call spends 1.2s waiting on 40 `adaptive-artifacts` subprocess spawns, and 0.9s idle in the asyncio loop. Python itself uses almost no CPU.
- The spawns come from `seeded` (record-by-record CLI creates) and from each dashboard load (8 `list` calls).
- The idle time comes from fixed `pilot.pause(0.1-0.5)` sleeps.
- `tests/test_e2e_dashboard.py` and the tmux tests take 7-13s each at HEAD. They are real end-to-end tests. Leave them on the real CLI.

Steps:
1. Build each seeded store once per session in `tests/conftest.py`. Copy it per test.
2. Give pure layout pilot tests a built snapshot instead of the CLI. Keep a few app tests on the real CLI.
3. Replace fixed `pilot.pause(<seconds>)` with a wait for the state the test needs.

Do not:
- raise any timeout or deadline.
- add pytest-xdist or any parallel runner.
- skip or delete tests.

Out of scope: the 6 tmux and e2e failures in the dirty working tree. They come from the uncommitted status-tabs change, which truncates the stat line to "Don" in the side pane. Measure on a clean HEAD worktree.

Start after task-navigation is done, because both edit the same tests.
