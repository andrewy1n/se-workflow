## Architecture

`load_snapshot` lists `project:phase` with `--full` so each phase body is in the snapshot. `phase_size` reads that body. `_phase_rows` stores the result on `PhaseRow.size`. `_task_rows` and `load_task_detail` store `payload.executor` on `TaskRow.executor` and `TaskDetail.executor`, using `subagent` when the field is missing or empty.

`section_cells` appends the size to the phase header. `title_cell` appends the executor to the task title. `detail_chips` adds the executor chip. No other screen changes. Phase detail already renders the body, so it does not gain a second size line.

## Interfaces

- `phase_size(body: str) -> str`. Matches a line `Size: one sitting`, `Size: more than one`, or `Size: more than one sitting`. Returns `one sitting`, `more than one`, or `""`.
- `PhaseRow.size: str = ""`.
- `TaskRow.executor: str`. `TaskDetail.executor: str`. Both are `inline` or `subagent`.
- Phase list joins `FULL_TYPES` (or the phase `list` call passes `--full`).
- Phase header label, when size is non-empty: `{title} {done}/{total} · {size}`, then any existing suffixes (evidence tally, release, awaiting sign-off). Clip the title portion so ` · {size}` remains.
- Task title: clip the title, then a dim ` · {executor}`, then the waits-on note.
- Chip text: `executor inline` or `executor subagent`, placed after the assignee chip when assignee is set, and in that slot when it is not.

## Decisions

glance-run-facts.

## Invariants

Displayed size is only `one sitting` or `more than one`. A missing executor is `subagent`. The phase header never appends an executor. Assignee is unchanged. The dashboard stays read-only.

## Assumptions

`plan-phase` keeps writing the Size line in the phase body. Work-items are already listed with `--full`. evidence-view may append further suffixes to the same header; size stays immediately after the done/total count.

## Tradeoffs

Loading phase bodies on every refresh adds the body text of every phase to the snapshot. That is smaller than a contract change, and it shows size for phases that already have the line. The parser accepts the two wordings already in the store rather than requiring a backfill.

## Risks

evidence-view is in progress and edits `dashboard/model.py`, `dashboard/tasks.py`, and `dashboard/task_detail.py`. This phase starts after that branch is on main, or the two will conflict. A Size line written in a form other than the three accepted wordings shows nothing. Title clipping must be tested at 60 columns or a long title will hide the suffix.
