subject: pane-width-stable
kind: repair
result: pass
revision: 8d1ef88
evidence: Failing before the fix: the new test test_stepper_fits_the_pane_after_its_scrollbar_appears fails without the watcher. The first version failed with rendered lines [..., '...retention rules and', 'a…'] against the expected 3 lines at width 56. The final version times out because pane.inner stays 58 while the content width is 56. With the fix, the targeted pair passes (2 passed). Before the test changes, the old stepper test still failed 3 of 4 full-file runs with the watcher in place: the test read the pane before it settled. Acceptance loop: `for i in $(seq 20); do uv run -q --with textual --with pytest --with pytest-xdist python -m pytest tests/test_dashboard_app.py -q -n 4 -p no:cacheprovider || break; done` gives 20/20 runs, each 204 passed. tmux: `uv run -q --with textual --with pytest python -m pytest tests -q -m tmux -rf` gives 11 passed.
observations: At 60x20 the status tab grid and the content push the pane past its height, so the vertical scrollbar appears after the first show. Content width goes from 58 to 56. The stepper keeps the 58-wide layout, so its last ellipsized line soft-wraps. The table title width, the needs-you list, the activity panel and the tab grid columns all use the same width, so they had the same bug. One fix covers all of them because refit calls show() again. I tried `scrollbar-gutter: stable` on .effort and dropped it: it always reserves 2 columns, and 6 tests at width 60 failed (status tabs no longer fit in one row, plus others). A separate flake showed up during the runs: ScreenStackError "No screens on stack" in test_effort_finished_mid_session_moves_last_and_dims. A TabActivated event arrived after teardown, and on_tabbed_content_tab_activated read self.focused. I guarded it with `if self.screen_stack and ...` in the same commit so the 20/20 target is reachable.
root_cause: Confirmed. Textual does not send a Resize event to a widget when its own scrollbar appears or disappears: the widget size stays the same and only scrollable_content_region shrinks. So EffortPane.on_resize never re-ran show(), and everything sized from self.inner stayed 2 columns too wide. Fix: EffortPane.watch_show_vertical_scrollbar schedules refit() (the old on_resize body) with call_after_refresh. Oscillation cannot happen: a narrower layout is never shorter, so the scrollbar stays once it appears. The old stepper test also checked the stepper before the layout settled. It now waits in _pane_settled until pane.inner == content width == stepper width, then pauses once.
verdict: pass
claim: Textual sends no Resize event when a widget's own scrollbar toggles. Any widget that lays content out from scrollable_content_region must also watch show_vertical_scrollbar. Separate claim: on_tabbed_content_tab_activated could raise ScreenStackError at app shutdown (a pre-existing teardown race, about 1 in 4 runs under -n 4). It is now guarded.
