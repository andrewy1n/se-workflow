## Requirements

R1: Each effort that has phase records opens on its default phase: the in-progress phase with the most recent activity; if none is in progress, the lowest-ordinal planned phase; if none, All phases.
R2: The selector line replaces the stepper. It shows earlier done phases as a muted count, the selected phase, every in-progress phase marked `●`, the next planned phase, and `All phases`. The selected segment is highlighted. A structured in-progress phase keeps its stage word. Segments wrap and clip by pane width as the stepper does today.
R3: `[` and `]` select the previous and next phase in ordinal order, with All phases after the last phase; they stop at the ends. `P` opens a picker listing All phases and every phase with its ordinal, state glyph, title, and done/total; typing filters it, Enter selects, Esc closes. Clicking a phase segment or `All phases` selects it; clicking the done count opens the picker.
R4: With a phase selected, the task table lists only that phase's tasks, with no section header rows, and Enter on any row opens the task. Status-tab counts cover only that phase. The progress bar covers that phase, and its label also shows the effort's done/total. The `/` filter applies within the selection.
R5: All phases shows the grouped table as before: collapsible phase headers, older done phases folded into one row, and effort-wide counts and progress.
R6: Needs you and Activity cover the whole effort whatever is selected.
R7: The selection follows the default (R1) until the user selects a different phase; it then stays pinned across refreshes. Selecting the phase that is the current default resumes following. A pinned phase that no longer exists falls back to following. Each effort keeps its own selection across effort switches in a session.
R8: `p` opens the selected phase's detail. In All phases it opens the cursor row's phase as before.
R9: The selected phase shows a wave strip: `w<n>` then one status glyph per task in that wave, for example `w1 ✓✓  w2 ▶  w3 ◌`. When it does not fit the pane, each wave shows one glyph for its least-finished task. The task table has no wave column.
R10: Activity merges consecutive items of the same kind and outcome into one line naming their subjects, for example `R1 R2 R3 R4 R7 insufficient → verify` or `4 checks passed: a, b, …`, clipped to the pane width. Failed items keep the error colour.
R11: Finished efforts are hidden by default. The tab bar shows `+N finished`, and `f` toggles showing them. A finished effort with any Needs you item stays visible.
R12: `?` shows the keys available on the current screen and focused widget, including `[`, `]`, `P`, and `f`.
R13: An effort with no phase records shows no selector and no wave strip, and its table renders as before.
R14: `dashboard/bin/dashboard --once` prints each effort at its default selection, including the selector line and wave strip.

## Acceptance criteria

R1, R4 counts, R6, R7, R9 strip text, R10, R11, and R13: model and task tests in `tests/test_dashboard_model.py` and `tests/test_dashboard_tasks.py` against seeded stores.
R2, R3, R4 rows, R5, R8, R11 toggle, and R12 on screen: Textual pilot tests in `tests/test_dashboard_app.py`.
R14: `tests/test_dashboard_integration.py` runs `--once` against a seeded store.

## Constraints

The dashboard stays read-only (constraint dashboard-read-only). No change to `contract/project-design.json` or `~/adaptive-artifacts`. Nothing executes until all five UX phases are discussed (constraint dashboard-ux-plan-before-execute).

## Non-goals

Spec, Evidence, and Journal views (spec-view, evidence-matrix, journal-view). Needs you labels, prompt copying, next-step line, landing state, and alerts (human-gates). Changing the status line segment.

## Invariants

The snapshot model stays independent of the selection: selection is UI state and filters a loaded `EffortView`. Needs you and Activity content do not depend on the selection. Status values and task order are unchanged.

## Assumptions

The Textual version `uv` resolves provides a key panel that `?` can toggle. "Most recent activity" for a phase is the latest `recorded_at` among the activity items for its tasks.
