## Requirements

R1: A waiting task's title cell does not include a `waits on …` note; unfinished dependencies are not listed in the task table row.
R2: Task detail still lists unfinished and finished depends-on links so the blocker list remains available without the row note.
R3: A waiting row with many unfinished dependencies stays one table line at typical dashboard widths (no wrap caused by dependency text in the title cell).

## Acceptance criteria

- Unit and pilot tests assert that a waiting row's title cell has no `waits on` substring and still shows the existing size/estimate/executor suffix.
- A pilot or unit case with several unfinished dependencies keeps a single-line title cell at 60 and 120 columns.
- Task detail still exposes Depends on links for those dependencies.
- Existing tests that expected `waits on …` in the row are updated to the dropped form.

## Constraints

none

## Non-goals

- Changing how `waits_on` is computed in the model.
- Changing status glyphs, quiet detection, or the task-detail Depends on / Blocks sections beyond relying on them for the list.
- Adding a count or truncated list in the row.

## Invariants

- One task row remains one visual line with respect to dependency text: the title cell must not introduce multi-line waits-on content.
- The model may still carry `waits_on`; only the row rendering drops it.

## Assumptions

- Users who need the blocker names open task detail (or already know them from the waiting status).
- The task column may still wrap for other reasons; this phase only removes waits-on as a wrap cause.
