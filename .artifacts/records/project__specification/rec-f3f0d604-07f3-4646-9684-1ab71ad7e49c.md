## Requirements

R1: When the user answers a continuity-question, decides a needs:human finding, or signs a manual check in an agent session, the parent session clears that Needs-you source at the event (question → answered; finding superseded with needs none; check-run corrected with signed_by set).

R2: engage lists open human-dismissible Needs-you items for the focus (open questions, needs:human findings, unsigned manual checks) and reminds the agent to clear them when settled; it does not refuse to route solely because those items are open.

R3: Skills that open those human gates (discuss, plan-phase, verify-work, execute-phase as applicable) document the matching clear command so closing is not left to ad-hoc memory.

R4: From the Needs you list or detail, the dashboard can dismiss the same human-dismissible kinds by invoking adaptive-artifacts CLI with the same transitions as the skills; loop-route, integration, and merge-branch items are not dismissible there.

R5: After a successful dismiss or skill clear, Needs you no longer shows that item on the next store refresh; failed CLI writes leave the item open and surface an error.

## Acceptance criteria

R1–R3: skill and kinds-and-focus text name the clear rules; `tests/test_skill_contract_consistency.py` still passes for every documented adaptive-artifacts invocation.

R4–R5: dashboard pilot tests dismiss a question, a needs:human finding, and an unsigned manual check via CLI stubs or a temp store, refuse dismiss on merge-branch (and other non-human kinds), and keep the item when the CLI fails.

## Constraints

Store records remain the authority; the dashboard does not keep a local dismissed set. Parent session remains the only writer from agent skills; dashboard writes only through adaptive-artifacts CLI for dismiss.

## Non-goals

Auto-inferring answers from chat without an explicit settle. Dismissing loop-route, integration, or merge-branch from the dashboard. Blocking engage routing until Needs you is empty.

## Invariants

Dismiss and skill clear produce the same lifecycle/payload outcomes for the same item kind. Human-dismissible kinds are exactly: blocking-question, open-question, needs-human, unsigned-check.

## Assumptions

The user who dismisses from the dashboard is allowed to sign as themselves (signed_by uses a configured or prompted identity). adaptive-artifacts is on PATH for the dashboard process.
