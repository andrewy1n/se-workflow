## Requirements

R1: A phase whose body has a `Size: one sitting` line shows `one sitting` on its task-table header, after the done/total count. `Size: more than one` and `Size: more than one sitting` both show `more than one`.
R2: A phase body with no Size line shows no size text on the header.
R3: Each task title shows `inline` or `subagent` from `payload.executor`. A missing or empty executor shows `subagent`. The suffix stays visible when the title is clipped.
R4: Task detail shows a chip `executor inline` or `executor subagent` beside the assignee chip, using the same value as the title.
R5: The phase header does not show an executor. Both facts remain visible at 60 columns.

## Acceptance criteria

R1 and R2: model tests in `tests/test_dashboard_model.py` against seeded phase bodies, and a pilot in `tests/test_dashboard_app.py` at 60 columns.
R3 and R4: the same model tests for the three executor cases, and a pilot that opens the task and checks the chip, at 60 columns, including a title long enough to clip.
R5: the 60-column pilot asserts the phase header has the size suffix and no executor word taken from its tasks.

## Constraints

The dashboard never writes to the store. Facts come from `adaptive-artifacts list` JSON. No change to `~/adaptive-artifacts`, and no new payload field on `project:phase`.

## Non-goals

An hour estimate. A `size` field on the phase record. A new table column. Changing the `Size:` line that `plan-phase` writes. Showing one executor on the phase header.

## Invariants

A missing executor means `subagent`. The displayed size words are `one sitting` and `more than one`. Assignee stays a separate fact. Clipping removes title text and keeps the size and executor suffixes.

## Assumptions

The Size line is written by `plan-phase` in the phase body. Existing bodies use `one sitting`, `more than one`, and `more than one sitting`. Work-item payloads are already loaded in full, so `executor` is present without a new query. Phase bodies are not in the snapshot today.
