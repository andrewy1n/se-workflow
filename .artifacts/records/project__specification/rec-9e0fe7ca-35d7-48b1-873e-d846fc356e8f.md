## Requirements

R1: The Evidence tab of a structured phase shows one row per requirement id in the specification's order, with columns: id, requirement text, traced tasks as done/total, latest check-run for the requirement as result glyph, evidence kind, and age, assessment status (`unassessed` when none), and next stage (blank when verified).
R2: A row uses the error colour when its latest check-run failed or its status is `blocked`, the warning colour when its next stage is specify, design, or plan, or its confidence is low, the muted colour when unassessed, and the default colour when verified.
R3: Above the matrix a release line shows the latest release state (or `no release`), `n/m verified`, and the blockers: every requirement that is not verified, as `<id> <status>` or `<id> → <next>`, clipped to the pane width with a `+k more` tail.
R4: Enter on a row opens that requirement's detail; Esc returns to the Evidence tab on the same row.
R5: Below 60 columns the matrix drops the text column; below 45 it also drops evidence kind and age. Id, status, and next are always shown, and the check result glyph is kept while it fits.
R6: The latest integration result and its conflicts stay on the Evidence tab below the matrix.
R7: On the main screen, a selected structured phase shows after its `R n/m verified` tally one glyph per requirement in id order: verified `✓`, failed check or blocked `✗`, routed upstream `↑`, unassessed `◌`, otherwise `·`, coloured as in R2. Clicking the glyphs or pressing `e` opens the phase screen on Evidence.
R8: A phase with no specification has no Evidence tab and no strip, as before.

## Acceptance criteria

R1 values, R2 colour classes, R3 blockers, R7 glyphs, R8: model tests in `tests/test_dashboard_model.py` and `tests/test_dashboard_requirement.py` against seeded stores, selected with `-k matrix`.
R4, R5 at 100, 55, and 40 columns, R6, R7 click: Textual pilot tests in `tests/test_dashboard_phase_screen.py`.

## Constraints

The dashboard stays read-only (constraint dashboard-read-only). No change to `contract/project-design.json` or `~/adaptive-artifacts`. Nothing executes until all five UX phases are discussed (constraint dashboard-ux-plan-before-execute).

## Non-goals

A requirement × acceptance grid. Effort-wide evidence across phases. Changing how status, next stage, or release ready are derived.

## Invariants

Status, next stage, and stage derivation come from the existing evidence model unchanged. Matrix rows and the strip use the same per-requirement values, so they never disagree. Row order is the specification's id order.

## Assumptions

The latest check-run per requirement carries `result` and `evidence_kind` and a `recorded_at` time, as the requirement detail already reads them. The latest assessment carries `confidence`.
