## Rationale

The dashboard derives "finished" when every phase and counted task of an effort is done, and shows those efforts dimmed and last. That tells you the work is really done without any record change. Closing is separate and explicit: `payload.status` (`open` | `closed`) on the goal and position, set by superseding them. execute-phase closes an effort only when the user says no more phases follow, and an effort is reopened by superseding with `status: open` (kinds-and-focus, Closing and reopening). The goal lifecycle (active -> superseded) stays as it is: it tracks record versions, not effort state.

## Counter-argument

Two signals can disagree: an effort can be finished but still open, or closed while someone plans a new phase without reopening it first. The skills now say to reopen before adding a phase, but nothing enforces it.
