## Rationale

`project:feedback` already means an external signal engage routes straight into discuss, with an explicit rule that nothing collects it. Deferred work needs park, list, and later promote — a different lifecycle. A separate `project:backlog-item` type keeps that signal clean and matches the gap in issue #4 without rewriting engage's feedback path.

## Counter-argument

Widening feedback with open/parked/promoted statuses would avoid a seventh evidence-loop-era type and reuse an existing name. The cost is conflating "route now" with "park for later," which forces every engage reader to reinterpret feedback and weakens the current "do not collect" rule.
