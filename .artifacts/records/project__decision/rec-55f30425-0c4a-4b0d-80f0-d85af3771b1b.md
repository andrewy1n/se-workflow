## Rationale

`release` state `ready` means every requirement assessment for the phase is `verified`. It records that the evidence is sufficient to land. It does not mean the branch is merged, an artifact exists, or a deploy ran. This phase writes `ready` only. Landing may later record `merged`. The other states stay in the enum so a later phase can use them. Nothing in this phase deploys.

## Counter-argument

Calling the last stage release invites a reader to treat it as deployment. Collapsing `ready` into `deployed` would make a verified phase look shipped, and the dashboard would lose the difference between evidence and production.
