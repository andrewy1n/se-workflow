## Rationale
The skill only fires when the user wants a review, so a user-invoked skill adds no always-loaded description. Targets sit in a disclosed file so the main skill stays short. Evidence from the aggregate keeps proposals specific to measured sessions.

## Counter-argument
A user-invoked skill depends on the user remembering it exists. A model-invoked skill could trigger itself after long sessions, but it would pay context load on every turn and could propose edits nobody asked for.
