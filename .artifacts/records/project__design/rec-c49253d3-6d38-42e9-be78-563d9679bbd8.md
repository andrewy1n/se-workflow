## Architecture

Change is confined to task-table title rendering in `dashboard/tasks.py` (`title_cell`): stop appending the `waits on …` note. Model field `TaskRow.waits_on` can remain for any non-row consumers or future use; this phase does not require removing it. Task detail continues to show Depends on / Blocks from `task_detail.link_options`. Update unit and app/tmux pilots that asserted the row note.

## Interfaces

- `title_cell(task, width, colors, indent="")` — for `status == "waiting"`, render title + size/estimate/executor suffix only; no `waits on` suffix.
- Tests: `tests/test_dashboard_tasks.py`, `tests/test_dashboard_app.py`, and any tmux needles that required `waits on` in the table row.

## Decisions

- drop-waits-on-from-row

## Invariants

- Title cell for waiting tasks must not contain the substring `waits on`.
- Dependency membership for display remains available via task detail Depends on links.

## Assumptions

- No other dashboard surface (activity, Needs you, phase tasks tab) depends on the row waits-on note for correctness; grep and fix any that do as part of the same change.

## Tradeoffs

Dropping the note maximizes row density and simplifies clipping rules; it costs at-a-glance blocker identity until the user opens detail.

## Risks

- Tmux / snapshot pilots that key off `waits on <slug>` in the table will fail until updated to another marker (title, status, or detail).
- If some workflow relied on copying blocker slugs from the row text, that path is gone; detail and copy actions remain.
