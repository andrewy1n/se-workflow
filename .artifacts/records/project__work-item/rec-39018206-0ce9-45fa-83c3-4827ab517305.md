## Description

Remove the `waits on …` suffix from waiting task title cells so long dependency lists no longer wrap rows. Keep blocker names available on task detail.

## Approach

1. In `dashboard/tasks.py` `title_cell`, delete the `note` that builds `  waits on …` from `task.waits_on`; leave `task_suffix` (size / estimate / executor) unchanged. Do not remove `TaskRow.waits_on` from the model.
2. Rewrite `tests/test_dashboard_tasks.py` `test_title_cell_clips_and_notes_what_a_waiting_task_waits_on` so a waiting row with deps has no `waits on` and still shows the muted suffix; keep title clipping behavior.
3. Rewrite `tests/test_dashboard_app.py` waiting-row pilots (`test_waiting_row_title_ends_with_muted_waits_on_its_unfinished_dependencies` and any helpers/assertions that key off `waits on` in the title cell, including estimate suffix order and detail-open needles) to assert absence of `waits on` and identify waiting rows by title/status instead.
4. Add a unit or pilot case with several unfinished dependencies at width 60 and 120: title cell plain text has no newline and no `waits on`.
5. Keep a regression that opening task detail still shows `Depends on:` links for unfinished deps (`task_detail.link_options` / existing detail pilots).
6. Update `tests/test_tmux_integration.py` needle `waits on fx-running` to another stable marker (waiting title or status) so the popup still proves the waiting row renders.
7. Run: `uv run --with textual --with pytest python -m pytest tests/test_dashboard_tasks.py tests/test_dashboard_app.py -q -k 'waits or title_cell or waiting_row or Depends'` (and the touched tmux test if run locally with `-m tmux`).
