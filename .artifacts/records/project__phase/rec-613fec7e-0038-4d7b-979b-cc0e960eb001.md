## Problem

Closing a phase updates the store and leaves git for a later question. The changes are already on the shared checkout, so commit, merge, and push get decided after the files exist. Parallel phases share that checkout.

## Approach

Decisions: phase-worktree, landing-close, store-primary.

Each phase body records a Landing section before plan review: branch `phase/<phase-slug>`, worktree `<repo-parent>/<repo-name>--<phase-slug>`, base `main`. On the phase gate, commit code on that branch, merge it into `main`, then commit the store on the primary checkout. Push happens only when the phase lists it under human stops. Incidental work stays in the current checkout. A phase with no Landing section stays in the current checkout so older phases still run.

The parent writes `.artifacts` only on the primary checkout. The phase branch does not commit the store. Inline work and subagents write code only under the worktree's absolute path.

Size: one sitting.
Stops: plan review before dispatch. No push. No manual sign-off.
Collisions: `plan-landing-rules` owns `skills/plan-phase/SKILL.md`, `skills/kinds-and-focus.md`, `README.md`, and `tests/test_plan_landing.py`. `execute-landing` owns `skills/execute-phase/SKILL.md` and `tests/test_execute_landing.py`. `verify-phase-landing` owns `tests/test_phase_landing.py`.

## Landing

- branch: `phase/phase-landing`
- worktree: `/home/andrewyin/se-workflow--phase-landing`
- base: `main`
- close: commit code on the phase branch, merge into `main`, then commit the store on the primary checkout
- push: not a stop

## Exit criteria

- `plan-phase` requires a Landing section (branch, worktree, base, close, and push only as a named stop) before plan review, and incidental work skips it. `python3 -m pytest tests/test_plan_landing.py -q` passes.
- `execute-phase` creates the worktree, confines code writes to it, keeps store writes on the primary checkout, commits the branch, merges to `main`, commits the store, and does not push unless Landing names push as a stop. A phase with no Landing stays in the current checkout. `python3 -m pytest tests/test_execute_landing.py -q` passes.
- The two skills name the same landing. `python3 -m pytest tests/test_phase_landing.py -q` passes.
