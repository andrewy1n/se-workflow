## Problem

Verification tasks take 20 to 80 minutes. Each one runs the phase's own checks and then the full suite, which repeats the same dashboard pilot tests. A failure is fixed inside the verification task and the suite is run again. The parent often runs those commands a second time. One serial run of the dashboard app and requirement pilots is 506 seconds. One full non-tmux suite is about 4 minutes and still growing, plus a serial tmux leg of about 90 seconds.

## Approach

Decisions: phase-checks-only, verify-stop. Run as structured work: specification `verify-budget`, design `verify-budget`.

A verification task runs that phase's integration check through the real entry point and the tests the phase's exit criteria name. It does not run the full suite, and it does not run `tests/test_dashboard_app.py` without a `-k` filter for this phase. `AGENTS.md` and `CLAUDE.md` tell a task to run its own `verify_command` at close.

When a check fails, the executor returns fail and does not edit the tree. `verify-work` leaves the work-item `in_progress` and the assessment uses `next` `execute`.

Planned full-suite acceptances on `verify-spec-view`, `verify-evidence-matrix`, and `verify-journal-view` are superseded with the phase-scoped command before those tasks dispatch, and those work-item approaches drop the full-suite step.

Tasks:

1. `budget-instructions` — subagent, 35m. `tests/test_verify_budget.py` first, then `skills/plan-phase/SKILL.md`, `skills/execute-phase/SKILL.md`, `skills/verify-work/SKILL.md`, `AGENTS.md`, and `CLAUDE.md`.
2. `narrow-planned` — inline, 15m, after `budget-instructions`. Supersede the three `*-suite` acceptances and edit the three work-item bodies. The parent writes the store.
3. `verify-verify-budget` — subagent, 10m, after both. Run the instruction tests and the store check. Do not edit the tree.

Size: one sitting. Human stops: plan review. Do not push.

Collision notes: wave 1 is only `budget-instructions`, which owns the skill files, `AGENTS.md`, `CLAUDE.md`, and `tests/test_verify_budget.py`. Wave 2 is only `narrow-planned`, which owns acceptances `rec-69e66203-14dc-40b6-97b6-f751fd52a9fb`, `rec-242ca52f-0229-46fb-8334-e9d041b5c06d`, and `rec-fea0aa6a-b7e5-4df3-824b-d015bc080c01`, and work-items `rec-79a4e4c1-cfcb-421b-a023-64563ff645f3`, `rec-8432d854-983c-4de9-bb0f-f99b94ecae9a`, and `rec-f04fa83f-a51f-4800-b3be-9b658df17590`. The waves do not share files.

## Exit criteria

- `tests/test_verify_budget.py` and `tests/test_skill_contract_consistency.py` pass (`uv run --with pytest python -m pytest tests/test_verify_budget.py tests/test_skill_contract_consistency.py -q`).
- The active `verify-spec-view-suite`, `verify-evidence-matrix-suite`, and `verify-journal-view-suite` acceptances are phase-scoped, and those three work-item bodies do not say to run the full suite. Observed through `adaptive-artifacts` `list` and `get` (the check command on `narrow-planned`).
