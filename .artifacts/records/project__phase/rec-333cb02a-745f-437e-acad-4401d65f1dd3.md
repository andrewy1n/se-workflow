## Problem

Work that is noticed but not yet part of a phase has nowhere to go in the store. It lives in chat or in GitHub issues outside the store. `project:feedback` only routes immediate new intent into discuss; it is not a parkable backlog. Humans also need to see and clear parked items without stuffing them into Needs you.

## Approach

Add `project:backlog-item` as `current-status` with required `effort` and `status` (`open` | `promoted` | `dismissed`), optional `source` / `phase`. Keep `project:feedback` as observation with unchanged engage semantics. Parent session captures via CLI when the user parks work; engage lists open items and offers capture/promote. Promote supersedes to `promoted` and routes to discuss with a new phase (or incidental); dismiss supersedes to `dismissed`. Handoff shows open items per effort. The dashboard effort pane gets a separate **Backlog** panel; promote/dismiss use the CLI and promote copies an agent prompt. Decisions: backlog-vs-feedback, backlog-effort-scope, backlog-promote, backlog-capture, backlog-item-pattern, backlog-dashboard-surface, backlog-dashboard-actions.

Session shape, waves, and Landing are set in plan-phase (plan-review still open — re-plan after this discuss).

## Exit criteria

- The bundled contract resolves `project:backlog-item` and still resolves `project:feedback` with unchanged engage semantics.
- Skills document create, list, and promote for backlog items with CLI invocations the contract allows; `tests/test_skill_contract_consistency.py` passes.
- A seeded store can create, list open items for an effort, and promote or dismiss an item without treating it as feedback, through the adaptive-artifacts CLI.
- The dashboard Backlog panel shows open items for the selected effort and supports promote/dismiss via the CLI path; Needs you does not list backlog items.
