## Problem

Work that is noticed but not yet part of a phase has nowhere to go in the store. It lives in chat or in GitHub issues outside the store. `project:feedback` only routes immediate new intent into discuss; it is not a parkable backlog.

## Approach

Add `project:backlog-item` as `current-status` with required `effort` and `status` (`open` | `promoted` | `dismissed`), optional `source` / `phase`. Keep `project:feedback` as observation with unchanged engage semantics. Parent session captures via CLI when the user parks work; engage lists open items and offers capture/promote. Promote supersedes to `promoted` and routes to discuss with a new phase (or an incidental work-item when that kind fits); dismiss supersedes to `dismissed`. Handoff shows open items per effort. Decisions: backlog-vs-feedback, backlog-effort-scope, backlog-promote, backlog-capture, backlog-item-pattern.

Session shape: one sitting. Human stops: plan review. Parallel tasks share the contract type name and CLI shapes — wave 1 owns `contract/project-design.json`; wave 2 skills and lifecycle tests do not edit that file. Wave 1 is contract (subagent). Wave 2 is skills docs and CLI lifecycle test (subagent, both depend on contract). Wave 3 is verification (subagent).

## Exit criteria

- The bundled contract resolves `project:backlog-item` and still resolves `project:feedback` with unchanged engage semantics.
- Skills document create, list, and promote for backlog items with CLI invocations the contract allows; `tests/test_skill_contract_consistency.py` passes.
- A seeded store can create, list open items for an effort, and promote or dismiss an item without treating it as feedback, through the adaptive-artifacts CLI.
