## Problem

A structured phase's evidence is spread out: the header shows only `R n/m verified`, the requirement list shows status and next stage without the checks behind them, and Activity repeats each assessment as its own line. Nothing says what still blocks release ready, and reading why one requirement is not verified takes opening its detail.

## Approach

Decisions: evidence-matrix-rows, evidence-release-line, evidence-strip. Run as structured work: specification `evidence-matrix`, design `evidence-matrix`.

The Evidence tab becomes a matrix (one row per requirement) with a release line of blockers above it. The main screen shows one glyph per requirement after the R tally; click or `e` opens Evidence. Starts after `spec-view` is on main.

Tasks (all `executor: subagent`):

1. `matrix-model` — extend `RequirementRow` and add `dashboard/matrix.py` (`row_tone`, `glyph`, `blockers`, `release_line`, `matrix_columns`). Cover with `-k matrix` model/requirement tests.
2. `matrix-ui` — EvidencePane DataTable, width column dropping, strip on selector with click meta. Depends on model. Cover with `tests/test_dashboard_phase_screen.py`.
3. `verify-evidence-matrix` — integration and full suite.

Collision notes: `dashboard/model.py` requirement rows belong to `matrix-model`. `EvidencePane` in `phase_screen.py` and `selection.selector_segments` belong to `matrix-ui`. Shares `dashboard/model.py` loaders with `journal-view` if that phase runs in parallel after both land on main — not a same-phase collision.

Size: one sitting. Human stops: plan review; then landing after verification.

## Exit criteria

- Row values, colouring rules, the release line's blockers, and strip glyphs hold against seeded stores (`tests/test_dashboard_model.py`, `tests/test_dashboard_requirement.py`).
- Column dropping by width, Enter opening the requirement detail, and the strip click hold in a Textual pilot (`tests/test_dashboard_phase_screen.py`).
- The full suite passes.
