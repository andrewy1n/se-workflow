## Problem

A structured phase's evidence is spread out: the header shows only `R n/m verified`, the requirement list shows status and next stage without the checks behind them, and Activity repeats each assessment as its own line. Nothing says what still blocks release ready, and reading why one requirement is not verified takes opening its detail.

## Approach

Decisions: evidence-matrix-rows, evidence-release-line, evidence-strip. Run as structured work: specification `evidence-matrix`, design `evidence-matrix`.

The Evidence tab of the phase screen becomes a matrix with one row per requirement in id order: id, text, traced tasks done/total, latest check-run (result, evidence kind, age), assessment status, and next stage. Problem rows are coloured. A release line above it gives the release state, n/m verified, and what blocks ready. In a narrow pane the text column goes first, then evidence kind and age; id, status, and next always stay. On the main screen the selected structured phase shows one glyph per requirement after the `R` tally, and clicking it or `e` opens the Evidence tab.

This phase edits the dashboard and does not change `contract/project-design.json` or `~/adaptive-artifacts`. It starts after `spec-view` is on main, because it replaces that phase's Evidence tab.

## Exit criteria

- Row values, colouring rules, the release line's blockers, and strip glyphs hold against seeded stores (`tests/test_dashboard_model.py`, `tests/test_dashboard_requirement.py`).
- Column dropping by width, Enter opening the requirement detail, and the strip click hold in a Textual pilot (`tests/test_dashboard_phase_screen.py`).
- The full suite passes.
