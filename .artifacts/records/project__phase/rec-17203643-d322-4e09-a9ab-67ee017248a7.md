## Problem

When a phase gate passes, the session stops. The next phase starts only if the user asks, and the question of whether to close the effort is asked in chat. Plan review survives the chat because it is a blocking continuity-question. Close and continue do not, so a finished effort stays open and the next phase waits on a fresh prompt.

## Approach

Decision: next-gate-continuation.

When the phase gate holds and a later phase of this effort is still planned, this session continues into the next gate and stops there. If that phase has no decision, follow discuss and stop for the user's choice. If it already has a decision, follow plan-phase, which opens the plan-review question and stops. Do not dispatch.

When no planned or in_progress phase remains, open one blocking continuity-question on the effort, scope `close-effort:<effort-slug>`, owner user. Do not close the goal in that step. The next session reads the question. Answering it by closing supersedes the goal and position with `status: closed`. Answering it by naming more phases marks the question answered and starts discuss on the new phase.

engage uses the same rule on resume. An open close-effort question stops the session on that question. A planned phase with no decision routes to discuss. A planned phase whose plan-review question is still open waits. Ready work routes to execute-phase.

A per-effort constraint that tells the agent to skip discuss and plan-review still applies to that effort. This phase does not withdraw those constraints.

## Exit criteria

- `tests/test_next_gate.py` asserts that execute-phase, after the gate, continues into discuss or plan-phase, and that when nothing remains it creates a blocking `close-effort:` question and does not supersede the goal to closed. `python3 -m pytest tests/test_next_gate.py -q` passes.
- The same test asserts engage routes a later session by that same rule, and that the README skill table states a passed phase continues to the next gate.
